⚠️
EXPERIMENTAL — somente AMD64.

O Renux está em constante desenvolvimento. Os recursos apresentados aqui podem ainda não estar todos presentes, e o sistema atualmente suporta apenas amd64 (x86-64). O RSL (Renux Subsystem for Linux) é planejado para o futuro, e o instalador ainda está em desenvolvimento.

Sobre

O Renux é um sistema operacional BSD moderno, projetado para ser fácil de manter e depurar, com foco em portabilidade e desempenho. Toda a árvore é feita para ser compreensível e modificável, e compila a partir de um único script portável em qualquer host Unix.

Recursos

sched_renux

Um agendador derivado do ULE, agora o padrão, ajustado para desempenho em cargas limitadas pela CPU, com balanceamento agressivo e roubo de trabalho preemptivo.

RENUX_MALLOC

Um fork do kern_malloc sem bloqueio, com caches profundos por CPU, habilitado por padrão no GENERIC.

VFS agressivo

renux_vfs_cluster e renux_vfs_subr oferecem padrões agressivos de agrupamento de I/O para vazão de armazenamento.

Preempção total

O FULL_PREEMPTION ativado por padrão no GENERIC reduz a latência de despacho no núcleo.

build.sh no estilo NetBSD

Um único script para tudo: ./build.sh build para world e kernel, além de iso, qemu e release.

Cross-build portável

Compila a partir de FreeBSD, Linux, NetBSD, OpenBSD, DragonFly ou macOS, sem nenhuma cadeia de ferramentas pré-instalada.

Separação MD/MI

O código dependente de máquina fica em sys/arch/, mantendo a maior parte do núcleo independente de máquina e pronta para novos ports.

Hackeável por projeto

Um único build.sh para toda a árvore, um núcleo independente de máquina e um cross-build autossuficiente em qualquer host Unix fazem do Renux um sistema fácil de entender, modificar e recompilar.

Obter Renux

Clone a árvore de fontes e compile você mesmo:

user $ git clone https://github.com/renuxproject/src.git /usr/src/renux
user $ cd /usr/src/renux
root # ./build.sh build
root # ./build.sh iso
root # ./build.sh qemu

Roteiro

  • Feito Separação MD/MI: código dependente de máquina em sys/arch/; o restante do núcleo é independente de máquina.
  • Em desenvolvimento Instalador: um instalador de primeira classe para colocar o Renux no disco, guiado pelo bsdinstall na imagem ao vivo.
  • Planejado RSL — Renux Subsystem for Linux: rodar programas Flatpak e de linha de comando Linux via uma VM bhyve (Alpine/Void Linux) mostrada na tela do Renux. Ferramentas planejadas: rsl-init, rsl-shell, rsl-install (C99 + Zig build).
  • Planejado Mais arquiteturas: portar além do amd64 — i386, arm64, RISC-V, PowerPC e outras são o alvo atual para portabilidade.
  • Planejado Linuxulator: executar binários Linux nativamente no núcleo.
  • Planejado Shell e utilitários em Zig.
  • Planejado Zig build como orquestrador alternativo de compilação.

Conduzido pela Comunidade & Descentralizado

O Renux é um projeto conduzido pela comunidade e descentralizado por princípio. Não existe uma autoridade central, empresa ou plataforma que possua ou controle o Renux.

O desenvolvimento e a infraestrutura podem ser distribuídos entre diferentes pessoas, comunidades e organizações, que podem manter seus próprios repositórios, espelhos, serviços e versões do sistema.

Qualquer pessoa pode obter o código-fonte, hospedá-lo onde quiser — em uma forge própria, espelho ou tarball — e construir sua própria versão do Renux. Forks, variantes e esforços independentes são partes legítimas do ecossistema e não são tratados como concorrência.

Não existe um único caminho para o Renux. Existem projetos independentes que compartilham uma mesma filosofia.

Política de descentralização ›

Como a Descentralização Funciona

  • Governança — nenhuma pessoa ou entidade tem autoridade absoluta; decisões importantes são públicas e abertas à discussão.
  • Espelhos e infraestrutura — o repositório não é um ponto único de falha; qualquer um pode hospedar um espelho ou forge e continuar desenvolvendo.
  • Forks — forks e variantes são cidadãos de primeira classe; nenhum precisa de permissão para se chamar Renux.
  • Distribuição — não existe repositório oficial obrigatório; comunidades mantêm os seus e usuários escolhem em quem confiar.

Hackeabilidade

Ser hackeável faz parte da filosofia do Renux: o sistema é feito para ser entendido, modificado e recompilado por quem o usa. O que o mantém hackeável:

  • Um único script de build — ./build.sh build recompila world e kernel; sem exigir cadeia de ferramentas pré-instalada.
  • Núcleo independente de máquina — o código MD fica em sys/arch/, então hackear um port toca um só lugar.
  • Componentes modulares — kernel, init, libc e userland podem evoluir de forma relativamente independente.
  • Qualquer host Unix — cross-build a partir de FreeBSD, Linux, NetBSD, OpenBSD, DragonFly ou macOS.
  • Seu próprio Renux — conduzido pela comunidade e favorável a forks: hackear o sistema pode virar a sua própria linha de desenvolvimento.
